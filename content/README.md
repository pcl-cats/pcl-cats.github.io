# 内容维护说明

网站内容都是 Markdown 文件，图片放在 `public/images/`。改完后运行 `npm run check:content`，再 `npm run build` 确认能生成。

| 内容 | 位置 | 怎么写 |
| --- | --- | --- |
| 猫猫档案 | `content/cats/<id>.md` | 每只猫一个文件，`id` 和文件名一致，建好后不要改 |
| 日记 | `content/diary/YYYY-MM-DD.md` | 每天一篇，同一天的几件事写在一起 |
| 大事记 | 日记里加 `milestone: true` | 不另写一份 |
| 漫画 | `content/comics/NN.md` | 每期一个文件，图片按阅读顺序列出 |
| 关于我们、和猫猫相处 | `content/about.md`、`content/guide.md` | 不写维护者的真实姓名 |

## 猫猫档案

常用字段：`name`、`photo`、`status`（`园区活动` / `已领养` / `失踪`）、`appearance`（花色）、`birthMonth`（如 `2024-06`）、`sex`、`sterilized`、`relations`。不知道的字段直接省略。`relations` 里的 `cat` 填对方的 `id`，`label` 写“妈妈”“儿子”“兄弟姐妹”这样的关系。

卡通形象：把图片放成 `public/art/cats/<id>-1.webp` 到 `-6.webp`，档案页就会出现，点一下换一个姿势。

## 日记

至少写 `date` 和 `title`。写到已建档的猫，把它们的 `id` 填进 `cats`，这篇日记就会出现在猫的档案页。有合适的照片就填 `cover`，它会成为列表里的小图。正文是普通 Markdown，可以插图。

### 哪些算大事记

领养、成功救助、一批猫完成绝育、义卖和文创上新、猫猫食堂这类设施的升级，以及之后回头看还会想起来的日子。日常的添粮、驱虫、复查不算。

## 文字风格

网站上的字要像照顾猫的人自己写的：朴实、平和、具体。

- 直接写发生了什么。比如“11 月 12 日晚上，在地下车库的捕猫笼里抓到了它”，而不是“记录提到”“原档案记载”“来源中有差异”。
- 用正面的说法。比如写“远远地看看它们也很好”，不写“页面内容不应被当作实时信息”这类免责声明。
- 不写口号和排比，不加英文小标题。
- 资料互相矛盾时，按更晚、更具体的那条写；拿不准的就不写。
- 日期写成“2026 年 11 月 22 日”，数字和汉字之间留空格。
- 保留原文里大家写的俏皮话，比如“难抓榜榜上有名”。

## 不需要手动改的

页脚的“最近更新”日期、首页的猫猫数量和月份插画都是自动生成的，不用改代码。
